# ゲームプレイシステム

各 Phase で実装するシステムの仕様。Issue 本文を一次情報として起こしている。
未実装のセクションは着手時に追記する。

## Section 1: プレイヤー（Phase 2 / Issue #11）

### 1.1 構成

| クラス | 種別 | 責務 |
| --- | --- | --- |
| `PlayerStats` | Pure C# (`SB.Domain`) | HP / スタミナ / 悴みの計算 |
| `IPlayerStatsConfig` | interface (`SB.Domain`) | 調整値の供給元 |
| `MovementModeResolver` | Pure C# (`SB.Domain`) | 入力 → 姿勢（MovementMode）の決定 |
| `PlayerLookState` | Pure C# (`SB.Domain`) | 視点角度の累積・クランプ |
| `PlayerStatsSO` | ScriptableObject (`SB.Player`) | 調整値アセット |
| `PlayerLookSettingsSO` | ScriptableObject (`SB.Player`) | マウス感度・ピッチ制限 |
| `PlayerInputReader` | MonoBehaviour (`SB.Player`) | Input System との唯一の接点 |
| `PlayerMovement` | MonoBehaviour (`SB.Player`) | CharacterController の駆動 |
| `PlayerLook` | MonoBehaviour (`SB.Player`) | ヨー（体）/ ピッチ（カメラ）の適用 |
| `DebugStatusHud` | MonoBehaviour (`SB.UI`) | 仮 UI（Phase 10 で置き換え） |

ルール（計算）と Unity（描画・入力）を分離しているため、速度・スタミナ・視点の仕様は
すべて EditMode テストで検証できる。

### 1.2 移動速度

| 姿勢 | 速度 | 入力 |
| --- | --- | --- |
| 歩行 (Walk) | 8 m/s | WASD |
| ダッシュ (Sprint) | 14 m/s | WASD + Shift 長押し |
| しゃがみ (Crouch) | 4 m/s | C（トグル） |
| 伏せ (Prone) | 2 m/s | Z（トグル） |

**姿勢の優先度: Prone > Crouch > Sprint > Walk。**
しゃがみ・伏せ中はダッシュできない。しゃがみと伏せは相互排他で、一方に入るともう一方は解除される。

ダッシュは「Shift を押している」かつ「実際に移動入力がある」かつ「スタミナがある」場合のみ成立する。
立ち止まったまま Shift を押しても Walk 扱いになり、スタミナは減らない。

### 1.3 スタミナ

| 項目 | 値 |
| --- | --- |
| 最大 | 100 |
| ダッシュ時の消費 | -10 / 秒 |
| 非ダッシュ時の回復 | +5 / 秒 |
| 悴み 75% 以上での消費 | **× 2**（-20 / 秒） |
| 枯渇後の再ダッシュ可能ライン | 15 |

- 悴みペナルティは**消費のみ**に掛かり、回復速度には影響しない
- スタミナが 0 になると「消耗（Exhausted）」状態になり、15 まで回復するまでダッシュできない。
  このヒステリシスが無いと 0 付近でダッシュが点滅するため入れている（Issue には明記されていない追加仕様）
- 悴み（Cold）の**上昇・下降ロジックは Phase 5 の担当**。Phase 2 では値を保持してペナルティに使うだけ

### 1.4 視点

| 項目 | 値 |
| --- | --- |
| マウス感度 | 0.12 度 / delta（`PlayerLookSettingsSO` で 0.01〜2.0） |
| ゲームパッド感度 | 4.0 度 / 秒（別係数） |
| ピッチ制限 | -85° 〜 +85° |
| Y 軸反転 | 設定で切替可能 |

- ヨーは Player 本体、ピッチは CameraPivot に適用する
- 感度は毎フレーム SO から読むため、Play Mode 中に値を変えても即反映される
- マウスとゲームパッドは delta のスケールが違うため、感度係数を分けている
  （ゲームパッドのみ `Time.deltaTime` を掛ける）

### 1.5 姿勢による当たり判定・視点高さ

| 姿勢 | CharacterController 高さ | 視点高さ |
| --- | --- | --- |
| 立ち | 1.8 m | 1.6 m |
| しゃがみ | 1.1 m | 0.95 m |
| 伏せ | 0.6 m | 0.45 m |

遷移は 0.15 秒で `SmoothDamp` 補間する。高さ変更時は `center` も追従させ、
カプセルの足元が同じ地面に接したままになるようにしている。

`Assets/_Project/Scenes/Sandbox_Player.unity`

- Player プレハブ配置済み、仮 HUD 表示あり

## Section 5: ワールド・地形（Phase 3 / Issue #12）

### 5.1 生成方式

マップは**実行時にシードから生成**する（`WorldGenerator`）。TerrainData をアセットとして保存しない。

| 理由 | 内容 |
| --- | --- |
| リポジトリ肥大 | 700m 四方の TerrainData は数十 MB のバイナリになる |
| Play Mode の汚染 | アセット化した TerrainData を掘削すると、Play Mode 終了後も変更が残る |
| オンライン化 | Phase 12 ではシード（int 1 つ）を配るだけで全員が同じマップを再現できる |

決定性のため、乱数（`DeterministicRandom`）とノイズ（`SeededNoise`）は自前実装。
`System.Random` / `UnityEngine.Random` / `Mathf.PerlinNoise` はランタイムや Unity バージョンによる差異や
シード不可の問題があるため生成には使わない。

生成処理は段階ごとに独立したサブシードを使うので、ある段階の乱数消費が増えても他の段階はずれない。

```
WorldGenConfig (seed + 各種設定)
  └─ WorldBlueprint.Create
       ├─ WorldLayoutGenerator  … バイオーム領域・集落・小屋・焚き火・スポーン地点
       ├─ BiomeMap              … 任意の点のバイオーム判定・所属度
       ├─ TerrainHeightField    … 任意の点の標高（解析関数）
       └─ PropScatterer         … 木・岩の配置
  └─ WorldGenerator (MonoBehaviour)
       ├─ Terrain（高さ・塗り分け・木）
       ├─ 岩 / 小屋 / 井戸 / 柵 / 焚き火 の GameObject
       ├─ マップ境界の壁
       └─ TerrainDigSystem
```

`WorldBlueprint` 以下は MonoBehaviour を含まないため、EditMode テストでマップ全体を検証している。

### 5.2 マップとバイオーム

| 項目 | 値 |
| --- | --- |
| マップサイズ | 700m × 700m（原点中心、-350 〜 +350） |
| 標高レンジ | 0 〜 120m（平原の基準高 30m） |
| ハイトマップ | 1025 × 1025（約 0.68m 間隔） |
| 塗り分けマップ | 1024 × 1024 |

| バイオーム | 数 | 半径 | 地形 | 地面 | 木 | 岩 |
| --- | --- | --- | --- | --- | --- | --- |
| Plain | 背景 | — | 緩い起伏 ±3m | 雪 | 疎（白樺中心） | 疎 |
| Forest | 5 | 45–65m | なだらかな丘 +2m | 森の雪（暗め） | **密**（松中心） | 少 |
| Mountain | 4 | 60–85m | 山頂 +60m（±15%）、稜線ノイズ | 岩 | 中（松・枯れ木） | **密**・大岩多め |
| Valley | 1 | 幅 26–32m、長さ 220–300m | 谷底 -12m | 雪 65% + 岩 35% | 中 | 中 |
| DeepSnow | 3 | 40–60m | 吹きだまり +2.5m | 新雪（明るい） | 疎（枯れ木中心） | 少 |
| FrozenLake | 2 | 30–45m | 平坦な氷面（平原 -4m） | 氷 | なし | なし |

- **山は 4 象限に 1 つずつ**、マップ端寄りに配置し、中央を開けた戦場にする
- 領域どうしは中心距離 ≥ (半径の和) × 0.85 を保つ（0.85 < 1 なので境界は少し重なってなじむ）
- 境界は所属度が外周 25% でフェードし、ノイズで揺らして円形に見えないようにしている
- 重なった場合は優先度の高いバイオームが勝つ: FrozenLake > Mountain > Valley > DeepSnow > Forest > Plain
- 調整値は `BiomeSettingsSO`（バイオーム境界定義）と `WorldGenSettingsSO` にある

### 5.3 集落・小屋・焚き火

| 項目 | 値 |
| --- | --- |
| 集落 | 4 箇所（互いに 140m 以上離す） |
| 集落の構成 | 小屋 3 棟（中心から 14m、ドアは井戸向き）+ 井戸 1 + 焚き火 1 + 柵（半径 24m、出入口 2 箇所） |
| 散在小屋 | 8 棟（集落・他の小屋から 50m 以上） |
| 小屋の合計 | **20 棟**、すべてビーコン（緑の光柱、高さ約 60m）付き |
| 焚き火 | **20 箇所**（集落内 4 + 散在 16、互いに 30m 以上） |
| 焚き火の燃焼時間 | 90〜360 秒を均等に割り振ってランダム配布 → 5 分経過時点で約 5 箇所が残る |

- 小屋・焚き火は湖と山には置かない
- 集落（半径 26m）・散在小屋・焚き火の足元は**整地**する。整地は順番に適用し、
  集落内の焚き火は集落の高さを引き継ぐ（段差ができない）
- 小屋と井戸の足元は掘削不可
- 焚き火は暖まり半径 8m を持つ（Phase 5 の悴み回復で使う）。燃焼スケジュールは Phase 8 で天候フェーズ連動に置き換える
- 小屋のビーコンは Phase 6 でアイテムの有無に応じて表示を切り替える

### 5.4 木・岩

| 項目 | 値 |
| --- | --- |
| 木 | **1100 本**（Pine / Birch / DeadTree） |
| 岩 | **250 個**（Rock / Boulder） |
| 最小間隔 | 木-木 3m / 岩-岩 3m / 木-岩 2m |
| 除外 | 湖・集落の柵の内側・小屋/井戸/焚き火の周囲 2m・スポーン地点の周囲 6m |

候補点を一様に引き、その地点のバイオームの密度に比例した確率で採用する。目標数ちょうどに達するまで続け、
足りない場合は例外を投げる（静かに少なく生成しない）。

木は Terrain の Tree Instance として描画し（インスタンシング・カプセル当たり判定）、岩は GameObject として配置して
`StaticBatchingUtility` でまとめる。

### 5.5 掘削（DigSystem）

| 項目 | 値 |
| --- | --- |
| 入力 | 右クリック単発で 1 回、長押しで 0.25 秒ごとに連続 |
| 届く距離 | 4m（視線の先の地面） |
| 1 回の掘削 | 半径 1.2m、中心で 0.3m（中心 35% は全深さ、外側へなだらかに減衰） |
| 最大深さ | 2.0m |
| 壁の最大傾斜 | 45°（安息角） |
| 隠れられる深さ | 1.2m（しゃがみ高さ 1.1m を上回る） |

- 掘削深さは `DigField`（ハイトマップと同じ格子）で管理し、**生成時の高さからのオフセット**として Terrain に書き戻す。
  何度掘っても丸め誤差が蓄積しない
- `SetHeights`（DelayLOD 版ではない）で書き込むので、**当たり判定も即座に更新**される
- **安息角ルール**: 掘った結果どこかの壁が 45° を超えると、隣接点を崩して掘り下げる。
  雪が崩れるように溝は深くなるほど広がり、穴に落ちても歩いて出られる
  （プレイヤーの登坂限界は 50°、ジャンプは未実装）
- 1 回の掘削で取り除いた雪の体積を返す（Phase 6・7 で雪玉の獲得量に使う）
- Bot（Phase 7）も同じ `TerrainDigSystem.Dig` を通る。スコップ（Phase 6）は半径・深さの倍率で表現する

### 5.6 掘った深さによる地面の色

| 深さ | 地面 |
| --- | --- |
| 0 〜 0.25m | 元の地面（雪・森の雪・岩 …） |
| 0.25 〜 1.0m | 土 |
| 1.0m 〜 | 深い土（暗い茶色） |

各しきい値の手前 0.1m でなめらかに切り替わる。塗り分けは生成時と同じ関数（`TerrainPaintRules`）で
掘った範囲だけを再計算するため、元のバイオームの色を保持しておく必要がない。
